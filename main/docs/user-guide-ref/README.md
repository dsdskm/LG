# 통합 운영관제 사용자 가이드 (DOCX)

**메인 산출물은 `통합운영관제_사용자가이드_v1.0.docx`이다.** PPTX 버전은 절대 위치로
텍스트 상자를 배치하는 방식이라 실제 폰트로 줄바꿈될 때 겹침/오버플로우가 발생해
DOCX로 전환했다. 두 산출물은 `content.py`의 동일한 `SLIDES`/`COVER_SPEC` 데이터를
공유하며, 렌더러만 다르다 (`build_user_guide_docx.py` / `build_user_guide.py`).

내용을 고칠 때는 docx 파일을 직접 편집하지 말고 **`content.py`의 `SLIDES` 데이터를
고친 뒤 스크립트를 재실행**한다 (재실행 시 기존 docx는 덮어써진다).

## 재생성 방법

```bash
pip install python-docx   # 최초 1회
python build_user_guide_docx.py
```

- 페이지 크기: A4 세로 (21.0×29.7cm)
- 콘텐츠는 `content.py`의 `SLIDES` 리스트(선언형 dict)에 있다. 각 dict가 문서의
  한 섹션(제목+본문)을 만든다. 문구만 고칠 때는 이 파일만 수정하면 된다.
- 레이아웃/스타일(색상, 폰트, 표 형태 등)을 고칠 때는 `build_user_guide_docx.py`의
  `render_*`/헬퍼 함수를 수정한다.
- 목차·페이지 번호·챕터 러닝헤더는 절대 좌표 계산이 아니라 **Word 필드**
  (TOC / PAGE / STYLEREF)로 만들어져 있어 Word가 열 때 실제 페이지에 맞춰
  자동 계산된다.

## 문서를 열었을 때 해야 할 일

Word가 "이 문서에는 다른 파일을 참조하는 필드가 있습니다. 필드를 업데이트하시겠습니까?"
라고 물으면 **예**를 선택한다 (자동 업데이트 설정이 되어 있어 대부분 바로 채워진다).
목차 페이지 번호가 비어 있으면 목차를 클릭한 뒤 `F9`를 눌러 갱신한다.

## 화면 캡쳐 삽입 방법

python-docx는 Word 정식 검토 메모(comment)를 생성할 수 없어, 캡쳐 안내를
점선 테두리 박스 안에 직접 넣어 두었다 — `[화면 캡쳐 삽입 – 그림 N]` / `대상: ...` /
`조건: ...`.

캡쳐 삽입 순서:
1. `python build_user_guide_docx.py` 실행 시 콘솔에 출력되는 "캡쳐 자리표시 목록"
   (그림 번호, 캡션, 대상)을 참고해 실제 화면에서 캡쳐한다.
2. Word에서 해당 그림 번호의 점선 박스 안 텍스트를 지우고 캡쳐 이미지를 그 자리에
   붙여넣는다 (표 셀이므로 이미지 삽입 후 셀 테두리를 없음으로 바꿔도 된다).
3. 박스 아래 `그림 N. <캡션>` 텍스트는 그대로 유지한다.

## 알려진 제한사항

- 내용은 2026-08-13 기준 `apps/robot/docs/기능명세서.md` / `설계문서.md` 및 소스
  코드를 근거로 작성되었다. 이후 코드가 변경되면 두 문서와 실제 화면을 다시
  대조해 `content.py`를 갱신해야 한다.
- AI 로그 분석(`/robot/ailog`)은 의도적으로 별도 문서로 남기고 본문에서 제외했다
  (메뉴 구성표에는 행으로만 남아 있음).
- Windows 일부 환경(Controlled Folder Access 등 랜섬웨어 방지 기능)은 python.exe가
  `.docx`/`.pptx`를 직접 생성하는 것을 조용히 차단한다. 두 스크립트 모두 `.zip`으로
  저장한 뒤 이름을 바꾸는 방식으로 우회하므로, 재실행 시에도 별도 조치가 필요 없다.
- 표/글꼴이 실제로 어떻게 보이는지는 Word에서 직접 열어 확인해야 한다 (필자는 Word
  실행 환경이 없어 화면을 육안으로 확인하지 못했다).
