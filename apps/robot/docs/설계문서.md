## 2. 모노레포 구조와 모듈 페더레이션

pnpm workspace + turbo 기반 모노레포이며, `apps/robot`은 다른 서브앱(ota/cms/tms/learn 등)과 함께 아래 공용 패키지를 `workspace:*`로 참조합니다.

```
packages/
  apis/       axios 클라이언트, 인증/에러 처리, 도메인 API 모듈, env(.env.dev/.qa/.prod) 보관
  stores/     전역 zustand 스토어 (세션, 라우트, 사이드바, 테마, 언어, 반응형, AI 어시스턴트 등)
  ui/         공용 디자인 시스템 (MainLayout, OrganizationSelector, Toast 등)
  hooks/      공용 훅 (useLogin, useMqtt, useS3Upload, useTab 등)
  constants/  공용 상수 (역할/레벨, 라우트, 반응형 브레이크포인트)
  utils/      공용 유틸
locales/      공용 번역 리소스
```

`vite.config.js`는 `@originjs/vite-plugin-federation`으로 robot 앱을 **Module Federation Remote**로 노출합니다.

- `name: 'robot'`, `exposes: { './App': './src/App.jsx' }` → 상위 셸(Shell) 앱이 robot을 원격 모듈로 임베드할 수 있도록 제공
- `shared`: react/react-dom/react-router-dom/i18next/styled-components 등을 싱글톤으로 공유하여 중복 번들/컨텍스트 분리 문제를 방지
- robot 자체는 `remotes`를 선언하지 않음 → robot은 오직 **Exposer**(remote) 역할만 하고, 다른 원격 모듈을 소비하지는 않음
- `base: '/robot/'`, dev 포트 5175, 빌드 결과물은 공용 `apps-dist/robot`에 출력

## 3. 라우팅 및 접근 제어

`src/App.jsx`의 `appRoutes` 배열이 GNB 메뉴 구조와 라우트를 동시에 정의합니다.

```js
{ name, path, prefix, icon, element, accessLevel: number[], depth?: [...하위라우트] }
```

- `flattenRoutes()`가 `depth`(하위 화면)를 재귀적으로 펼쳐 `<Routes>`에 등록
- GNB에 노출되지 않는 보조 화면(`logreplay`, `tv`, `apitest`, `replaycontrols`, `sitedetail`)은 `appRoutes` 배열 밖에서 개별 `<Route>`로 별도 등록
- `accessLevel`은 [기능명세서 2장](./기능명세서.md#2-사용자-역할-및-메뉴-접근-권한)의 역할별 userLevel과 매칭되어 `MainLayout`이 메뉴 노출 여부를 제어
- 로그인 여부는 라우터 가드가 아니라 `App` 컴포넌트 최상단에서 `useUserStore.getState()`를 동기적으로 읽어 미로그인 시 `window.location.href = '/login'`으로 즉시 리다이렉트

## 4. 인증 / 세션 / 토큰 갱신

- 세션은 `@repo/stores`의 `useUserStore`에 저장되며 `sessionStorage`(`user-session` 키)에 persist됩니다.
  ```
  { isLoggedIn, session: { email, accessToken, refreshToken, userId, userRole, userLevel, expiresAt } }
  ```
- 로그인은 `@repo/hooks`의 `useLogin`이 처리하며, `userRole → userLevel` 매핑은 `@repo/constants`의 `USER_ROLE_LEVEL`을 사용합니다.
- **토큰 갱신**은 `@repo/apis`의 axios client 인터셉터에서 중앙 처리됩니다: 401 응답이면서 `accessToken`+`refreshToken`+`userId`가 있으면 조용히 토큰 갱신을 시도하고 성공 시 원 요청을 재시도, 실패 시 `logout()` 호출 후 로그인 페이지로 안내합니다. 갱신 불가능한 401은 즉시 로그아웃됩니다.
- `apps/robot/src/apis/common.js`의 `shouldForceLogout()`은 `AUTH_40101` 에러 코드 수신 시 강제 로그아웃 후 `/login?sessionout=Y`로 리다이렉트합니다(로그인 페이지에서 세션 만료 토스트로 노출).
- 로그아웃 시 `session`(accessToken/refreshToken 포함) 전체를 초기화합니다 — refreshToken이 남아 재사용되는 문제를 방지하기 위한 처리입니다.

## 5. 상태 관리

대부분의 전역 상태는 **`apps/robot`이 아닌 `@repo/stores`에 위치**해 다른 서브앱과 공유됩니다.

| 스토어 | 용도 |
| --- | --- |
| `useUserStore` | 로그인 세션 (위 4장) |
| `organizationStore` | 선택된 그룹/사이트 |
| `useAiAssistantStore` / `useAiLogEventStore` | AI 어시스턴트 패널/이벤트 상태 |
| `useThemeStore` / `useLanguageStore` / `useResponsiveStore` | UI 환경설정 |
| `useRouteStore` / `useSideBarStore` / `useErrorStore` / `useCountStore` | 라우팅/사이드바/에러/카운트 보조 상태 |

앱 로컬 상태:

- `src/utils/robotStore.js`: 대시보드 상태 카드 클릭 → 로봇 관리 목록으로 넘어갈 때 사용할 상태 필터(`operationStatusFilter`)를 임시로 들고 있는 zustand 스토어
- `src/common/AppContext.jsx`: `selectedGroup`/`selectedSite`를 트리 전체에 전달하는 React Context (인증/테마와 무관한 순수 UI 선택 상태)

## 6. 데이터 모델

### 6.1 조직/위치 계층

```
Group (그룹사)
 └─ Site (사업장, isDefaultSite: 미배정 로봇 풀)
     └─ Building (건물)
         └─ Floor (층, 지상/지하 + 층순서)
             └─ Area (구역)
```

각 Site는 자동으로 하나의 "기본 사이트(isDefaultSite)"를 가지며, 아직 어떤 사이트에도 배정되지 않은 로봇은 이 기본 사이트에 속한 것으로 취급됩니다.

### 6.2 로봇(Device)

```
Device {
  deviceId, deviceName, deviceModelName,
  deviceRegStatus (REGISTERED/ACTIVE/DELETE),
  deviceState, deviceSerialNumber, deviceMacAddress, deviceFirmwareVersion,
  provision: { isDefaultSite, groupId, groupName, siteId, siteName },
  state: { batteryState, position/pose, sitePosition, hwComponents, sensors, sWmodules, stateUpdatedAt },
  connection: { connectionUpdatedAt },
  tms: { tmsUpdatedAt, taskFlowState.taskFlows[{ id, name, operationStatus, isActive, isEnabled }] }
}
```

`src/utils/robotUtils.js`가 위 원본 데이터를 화면에서 쓰기 좋은 형태로 파싱하는 공용 함수(`parseDeviceInfo`, `parseRobotData`, `getWifiStatus`, `filterActiveTaskFlows` 등)를 제공합니다.

### 6.3 지도(Map)

맵은 `mapScope = { groupId, siteId, buildingId?, floorId?, areaId? }`(구역 맵) 또는 `{ deviceId }`(로봇 개별 맵)로 식별되며, 각 스코프마다 **NAVI(주행맵 zip)/POI(json)/SVG(도면)** 3종 파일이 독립적으로 버전 관리됩니다. POI/SVG 버전은 `baseNaviVersionId`로 특정 NAVI 버전을 참조합니다.

### 6.4 AI 이벤트 도메인

```
Event   : 로그에서 파생된 이상 탐지 레코드
          { robotId, func, summary, status, severity, confidence, createdAt, actions[] }
Func    : 이벤트 분류 단위(기능) — 자체 프롬프트/태그/담당자 보유
Action  : Func(또는 전체)에 적용 가능한 재사용 조치 정의
Assignee: Func에 배정되는 담당자(이름/이메일/팀)
```

Func가 이벤트를 분류·분석하는 프롬프트/담당자를 소유하고, Action은 Func 단위로 추천되는 조치를 정의하는 **N:M에 가까운 참조 관계**입니다.

## 7. 백엔드 API 구성

### 7.1 일반 도메인 API (`src/apis/*.js`)

REST 리소스별로 `get*/post*/put*/delete*` 패턴을 따르는 얇은 axios 래퍼입니다: `deviceApis`, `areaApis`, `buildingApis`, `floorApis`, `groupApis`, `siteApis`, `mapApis`, `userApis`, `authApis`, `termsApis`, `invitationApis`, `fileApis`.

- 로봇 원격 명령은 전용 엔드포인트 하나로 통일: `deviceApis.postInstanceActions(deviceId, { userId, actions })` — `actionType`/`blockingType`/`actionParameters`를 담은 액션 배열을 전송
- 맵/약관 업로드는 동일한 **사전 서명 URL 패턴**을 사용: ①업로드 URL 발급 요청 → ②해당 URL로 파일 직접 PUT(스토리지 서버) → ③완료 처리 API 호출로 메타데이터 확정

### 7.2 AI 마이크로서비스 (`src/apis/ai/*.js`)

AI 로그 관리 기능은 5개의 독립된 백엔드 서비스를 조합해서 사용하며, 서비스별로 base URL 환경변수와 axios 클라이언트(`shared.js`)가 분리되어 있습니다.

```
로봇 로그 ─▶ event_receiver ─▶ event_analyzer(LLM 분류/분석) ─▶ config_manager(기능/담당자/액션/리포트 설정)
                                                              └▶ action_runner(조치 실행)
                                                              └▶ report_manager(리포트 발송 이력)
```

| 서비스 | 환경변수 | 담당 |
| --- | --- | --- |
| event_receiver | `VITE_EVENT_RECEIVER_URL` | 원본 로그 수신, 에러 전후 컨텍스트 라인 추출 |
| event_analyzer | `VITE_EVENT_ANALYZER_URL` | LLM 분류/분석 파이프라인, 이벤트 목록/분석 결과 조회·수정 |
| config_manager | `VITE_CONFIG_MANAGER_URL` | 기능(Func)/LLM 프롬프트/담당자/리포트 템플릿/에러 컨텍스트 설정 저장소 |
| action_runner | `VITE_ACTION_RUNNER_URL` | 액션 카탈로그 CRUD 및 실행(`/actions/run`, 현재 더미 처리) |
| report_manager | `VITE_REPORT_MANAGER_URL` | 리포트 발송 이력 조회 (템플릿 자체는 config_manager가 소유) |

AI 챗봇(`ChatSettings`)은 위 5개와는 별도로 `@repo/apis`의 `ai_chat_service`를 사용하며, robot뿐 아니라 ota/cms/tms 전체에서 공유되는 설정입니다.

## 8. 실시간 통신 방식

웹소켓/MQTT를 상시 유지하는 구조가 아니라, **화면별로 필요한 곳에만 선택적으로** 적용되어 있습니다.

- **일반 폴링(주력 방식)**: 대시보드·TV 대시보드의 로봇 위치/상태, 로봇 상세의 "Live" 토글은 `setInterval` 1초 주기로 `deviceApis.getDevices`/`getDeviceInfo`를 재호출합니다. `document.visibilityState`/`hasFocus()`를 체크해 탭이 백그라운드일 때는 자동으로 멈춥니다. 응답의 타임스탬프 필드를 캐시와 비교(diff)해서 변경이 없으면 리렌더링을 생략합니다.
- **웹소켓**: 로봇 상세의 웹 콘솔 카드 중 실시간 플래그가 있는 카드(예: 3D 뷰)만 `wss://.../robot-tunnel?...`로 개별 연결하며, 탭별/로봇별/포트별로 고유 클라이언트 ID를 발급해 서버가 동시 세션을 구분합니다. 연결 끊김 시 최대 2회 재시도(5초 backoff)합니다. 수신 데이터는 `postMessage`로 내부 iframe에 전달됩니다.
- **AI 이벤트**: 10초 주기 폴링으로 이벤트 목록을 갱신합니다.

## 9. 지도/3D 시각화 아키텍처

- **2D 평면 지도** (`common/SiteMap.jsx`): SVG/PNG 도면을 캔버스에 그리고, ROS 월드 좌표 ↔ SVG 픽셀 좌표를 어파인 변환(`utils/mapUtils.js`)으로 매핑, 로봇 아이콘(상태별 색상+방향 화살표)과 POI를 오버레이합니다. 마우스 드래그/휠, 터치 핀치로 팬/줌을 지원합니다.
- **3D 지도** (`common/SiteMap3D.jsx`): 위 2D 컴포넌트를 감싸며, react-three-fiber로 SVG의 벽/바닥 속성(`data-height`/`data-base`/`data-unit`)을 3D로 압출(extrude)하거나 PNG 평면에 텍스처를 입혀 렌더링합니다. 오빗 컨트롤, 전체화면(모달 포탈), 2D/3D 토글 상태를 `localStorage`+`storage` 이벤트로 여러 탭(대시보드 ↔ TV 대시보드)에 동기화합니다.
- **카카오맵** (`Dashboard/KakaoMap.jsx`): SDK를 `autoload=false`로 지연 로드(`utils/kakaoLoader.js`, 10초 타임아웃 + Promise 캐싱)하고, 마커/툴팁/클러스터러 생성 각 단계를 try/catch로 방어해 지도 API 실패가 전체 화면을 깨지 않도록 처리합니다.

## 10. 로그 리플레이 기술 아키텍처 (MCAP/ROS/URDF)

로그 리플레이(`Logreplay`)와 로봇팔 분석 리플레이(`ReplayControls`)는 **동일한 MCAP 디코딩 인프라를 공유**하는 형제 도구입니다. ReplayControls는 실제로 Logreplay의 디코더 모듈을 그대로 import해서 사용합니다.

### 10.1 MCAP 스트리밍/디코딩

- `@mcap/core`의 `McapIndexedReader`를 커스텀 `HttpRangeReadable`(HTTP Range 요청 + 청크 캐싱) 위에서 사용 → 전체 파일을 내려받지 않고 필요한 부분만 스트리밍
- 압축 해제는 `fzstd`/`lz4js`
- 메시지 디코딩은 스키마별 분기: JSON/텍스트는 그대로, ROS1/ROS2 바이너리는 `@lichtblick/rosmsg*`, `@lichtblick/ros2idl-parser`로 처리. `/rosout` 로그는 속도를 위해 별도의 수제 CDR 파서로 직접 디코딩
- `package.json`의 `@foxglove/*` 의존성은 소스에서 실제 import되지 않는 **레거시 잔존 의존성**으로 확인됨 (Lichtblick 포크로 이전하기 전 사용하던 라이브러리로 추정)

### 10.2 워커 활용

- `workers/logSearch.worker.js`: FlexSearch 텍스트 색인을 Comlink RPC로 감싸 메인 스레드 블로킹 없이 로그 전문 검색을 수행
- `components/urdf/stlParseWorker.js`: STL 메시 파싱을 워커 풀(코어수-1개)로 병렬 처리 + 전역 메모리 캐시(`GLOBAL_MESH_CACHE`)로 반복 로드 시 재파싱을 방지

### 10.3 URDF 3D 로봇 모델 (ReplayControls)

- `urdf-loader` + `@react-three/fiber` + `@react-three/drei`(OrbitControls)로 URDF를 3D 렌더링. `public/urdf/<패키지명>` 폴더(`ButlerModel_ver2_bracket`, `hmc_v2_hand`, `cloid_description`)를 URDF 내부 패키지 참조에 매핑
- 매 프레임 `/joint_states` 샘플(현재 재생 시각과 가장 가까운 값을 이분 탐색으로 조회)을 `robot.joints[name].setJointValue(position)`로 적용해 3D 모델을 실제 동작과 동기화
- 정밀 구간(윈도우 샘플)과 저해상도 전체 타임라인 샘플을 상황에 맞게 섞어 사용해, 빠른 구간 이동(scrub) 시에도 끊김을 최소화

## 11. 다국어(i18n) 처리

- `src/i18n.js`가 `@repo/locales`(전역 공용 번역)와 `apps/robot/locales`(앱 전용 번역)를 언어별로 병합해서 초기화합니다.
- 지원 언어: `ko-KR`(기본), `en-US`, `ja-JP`
- robot 앱 전용 네임스페이스는 `route`(GNB 라벨)와 `robot`(지도 관리 등 기능별 문구) 2개뿐이며, 나머지(공통 레이아웃/로그인/에러 메시지 등)는 전부 `@repo/locales` 공용 리소스를 사용합니다.

> ⚠️ 새 번역 키를 추가한 뒤 화면에 반영되지 않는다면, Vite 캐시가 오래된 locale JSON을 물고 있는 경우가 있습니다 (`rm -rf apps/robot/node_modules/.vite`로 해결).

## 12. 빌드/환경 설정

| 스크립트 | 모드 |
| --- | --- |
| `dev` | vite dev server |
| `build` | `--mode prod` |
| `build:dev` | `--mode dev` |
| `build:qa` | `--mode qa` |

환경변수(.env.dev/.env.qa/.env.prod/.env.local)는 앱별이 아니라 **`packages/apis`에 중앙 배치**되어 있으며, `vite.config.js`가 `loadEnv(mode, '<repo>/packages/apis', 'VITE_')`로 로드해 `import.meta.env`에 주입합니다 — 모노레포 내 모든 서브앱이 모드별로 동일한 API 베이스 URL 세트를 공유하는 구조입니다.

## 13. 기술 부채 / 알아둘 점

- **레거시 의존성**: `@foxglove/*` 패키지들이 미사용 상태로 `package.json`에 남아 있음 (제거 검토 가능)
- **클라이언트 사이드 필터링**: SiteDetail의 3개 탭, 로봇 관리 목록 등 다수 화면이 전체 로봇 목록을 받아온 뒤 프론트에서 필터링함 — 로봇 수가 크게 늘어날 경우 서버사이드 필터/페이지네이션 전환이 필요할 수 있음
- **레거시 래스터 맵 디코딩**: 구버전 맵은 서버 렌더링 엔드포인트가 없어 PGM 파일을 클라이언트에서 직접 비트 디코딩함 (`MapHistory.jsx`)
- **권한 검증의 위치**: 역할별 화면/버튼 노출 제어가 대부분 프론트엔드 로직(세션의 userLevel 비교)에 있으며, 실제 인가는 백엔드가 별도로 수행한다는 전제
- **미완성 항목**: [기능명세서 13장](./기능명세서.md#13-현재-미완성비활성-기능) 참고
